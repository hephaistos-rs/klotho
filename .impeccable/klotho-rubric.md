# Klotho rubric

The Klotho gate's judge answers each item **PASS** or **FAIL**, with evidence (`file:line` or a screenshot name). Items marked **HARD** fail the gate on their own. Otherwise, the score is PASS items ÷ applicable items × 10, and the gate needs 8 or more.

"In scope" means the changed files given to the judge. `components/` counts only where a page uses it.

| # | Check | How to verify | Hard |
|---|---|---|---|
| R1 | **Tokens only.** No raw palette colour utilities (`gray-*`, `zinc-*`, `slate-*`, `neutral-*`, `stone-*`, `red-*`, `green-*`, `blue-*`, etc., nor `white`/`black` as colours) and no arbitrary colour values (`[#…]`, `[rgb(…)]`, `[oklch(…)]`) in `crates/web/src/**/*.rs`. | `grep -nE '(bg\|text\|border\|ring\|divide\|fill\|stroke\|outline\|from\|to\|via)-(gray\|zinc\|slate\|neutral\|stone\|red\|orange\|amber\|yellow\|lime\|green\|emerald\|teal\|cyan\|sky\|blue\|indigo\|violet\|purple\|fuchsia\|pink\|rose\|white\|black)\b\|\[#\|\[rgb\|\[oklch' crates/web/src` returns nothing. | HARD |
| R2 | **Theme complete.** `styles.css` defines every token in DESIGN.md (including `--shell*`, `--thread*`, `--success*`, `--destructive-soft/ink`, `--text-meta`) for light, and again under `.dark`, as OKLCH. There's exactly one `@import "tailwindcss" source(none)` and an `@source "./src/**/*.rs"`. | Read `styles.css`. | HARD |
| R3 | **Works without JavaScript.** Every navigation is an `<a href>`. Every state change is a `<form method="post">` with a submit button. Disclosure uses `<details>` or a page, not script. Nothing is hidden until the runtime runs. The theme toggle works as a plain form post. | Read the markup. Compare the JS-off and JS-on screenshots. | HARD |
| R4 | **WCAG AA contrast in light and dark.** Body and meta text ≥ 4.5:1. Large text, focus rings, input boundaries and meaningful graphics ≥ 3:1. Checked on the token pairs actually used together. | DESIGN.md's measured pairs, plus the screenshots for any pair not listed. | HARD |
| R5 | **Visible keyboard focus** on every link, button, input, checkbox, select and summary, using `ring`/`outline` from `--ring`. No `outline-none` without a `focus-visible:` replacement. | Grep for `outline-none` and check that each has a `focus-visible:` sibling. Check that components have focus styles. | HARD |
| R6 | **Self-contained.** No `http(s)://` URLs to fonts, icons, scripts or stylesheets in rendered markup or CSS. Fonts and icons come from the embedded bundle under `/-/assets/` (or are inlined SVG). | Grep `crates/web` and the generated CSS. Check the network list in the screenshot run. | HARD |
| R7 | **Monospace only for git-typeable things:** refs, hashes, paths, scope names, tokens, clone URLs and code. Never labels, headings, buttons or nav. | Grep `font-mono` and `<code>`, and inspect each use. | |
| R8 | **Vendored components, not hand-rolled controls.** Buttons, inputs, selects, checkboxes, alerts, badges and tables use `crates/web/src/components/` or their `*_variants` helpers. There are no parallel copies of an existing component. | Grep for `<button class=`, `<input class=` and `<select class=` outside `components/`. Each must go through a component or a variants helper. | |
| R9 | **No default-shadcn look left.** Radius is the Klotho radius (0.25rem base), not shadcn's 0.625rem. Fonts are the Klotho families, not the system default or Geist/Inter. Primary is indigo, not shadcn's near-black. The header is the indigo shell with the thread. | `styles.css` values plus screenshots. | |
| R10 | **The thread is only the thread.** `thread`/`thread-ink` classes appear only on the header thread, the current-nav marker, and the commit log line and beads (DESIGN.md P2 as accepted). | Grep for `thread`. | |
| R11 | **One type system.** Sizes come from the DESIGN.md hierarchy (`text-2xl` titles, `text-lg` sections, `text-sm` UI, `text-meta` details). Weights are 400, 500 and 600/650 only (no 700 or above; `font-semibold` renders 650). No arbitrary sizes such as `text-[…]`. | Grep for `text-[`, `font-bold` and `font-black`. | |
| R12 | **States covered.** Every interactive component has hover, focus-visible, active and disabled styles. Forms have an error state wired with `role="alert"` or `aria-describedby`. Lists have an empty state that says what to do next. | Read the components and pages. | |
| R13 | **Responsive at 390px and 1280px.** No horizontal page scroll at 390px. Rows wrap their actions. Tables scroll inside their own container. Header fits. | Screenshots at both widths. | |
| R14 | **Banned patterns absent:** gradient text, glassmorphism, coloured left or right border stripes over 1px, eyebrow labels above headings, emoji or Unicode glyphs used as icons, card grids for lists, nested cards, decorative motion over 200ms, cream grounds. | Grep plus screenshots. | |
| R15 | **Copy and semantics.** One `<h1>` per page. Headings in order. Labels tied to inputs. `aria-current="page"` on the current nav link. Buttons name their action. `<html lang>` is set. | Read the markup. | |
| R16 | **Long lines scroll in their block.** Code, diffs, clone URLs, secrets and other long unbreakable text sit in a container with `overflow-x-auto` (or `break-all` for secrets), so at 390px and 1280px the page itself never scrolls sideways. | Grep `font-mono`/`<pre>` containers for `overflow-x-auto` or `break-all`. Screenshots at 390px with a long line. | |
| R17 | **Warnings are icon plus text.** Every warning uses the `warning` tokens with an icon and words. Never a coloured line, stripe or border alone, and never the `thread` colour. | Grep for `warning`. | |
| R18 | **The thread is decorative to assistive tech.** Thread lines and beads are `aria-hidden="true"` or pure CSS borders, and the current nav link carries `aria-current="page"`. | Read the markup. | |
